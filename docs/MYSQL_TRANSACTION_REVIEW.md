# MySQL 事务复习

## 1. 什么是事务

事务是一组数据库操作的执行单元。

这组操作要么全部成功，要么全部失败。只执行一半是不允许的。

例如转账：

```text
A 账户扣 100 元
B 账户加 100 元
```

这两个操作必须放在同一个事务中。如果 A 扣钱成功，但 B 加钱失败，就会造成数据错误。事务可以保证出现异常时回滚到操作前的状态。

在 MySQL 中，常见事务语句有：

```sql
START TRANSACTION;
COMMIT;
ROLLBACK;
```

## 2. 为什么需要事务

事务主要解决写操作中的数据安全问题。

没有事务时，多个 SQL 连续执行，如果中间某一步失败，前面已经执行成功的 SQL 可能不会自动撤销，数据就会处于不完整状态。

事务可以保证：

- 多个写操作作为一个整体执行。
- 中间出错时可以回滚。
- 并发访问时尽量避免互相干扰。
- 提交后的数据能够持久保存。

在学生管理系统中，添加学生、修改学生、删除学生、批量删除学生都属于写操作，适合使用事务管理。

## 3. 事务的四大特性 ACID

ACID 是事务的四个核心特性：

- `A`：Atomicity，原子性。
- `C`：Consistency，一致性。
- `I`：Isolation，隔离性。
- `D`：Durability，持久性。

### 3.1 原子性 Atomicity

原子性表示一个事务中的操作要么全部成功，要么全部失败。

例如批量删除学生：

```text
删除学生 401
删除学生 402
删除学生 403
```

如果删除到一半发生异常，事务应该回滚，避免出现只删除了一部分学生的情况。

### 3.2 一致性 Consistency

一致性表示事务执行前后，数据库都必须处于正确、合法的状态。

例如：

- 学生成绩不能变成业务不允许的值。
- 学生创建人信息不能丢失。
- 批量删除时不能删除一部分成功、一部分失败后还当作成功返回。

一致性通常由数据库约束、业务校验和事务共同保证。

### 3.3 隔离性 Isolation

隔离性表示多个事务并发执行时，彼此之间要有一定隔离，不能随意看到对方未提交或不稳定的数据。

隔离性和 MySQL 的事务隔离级别有关。隔离越强，并发问题越少，但性能可能越低。

### 3.4 持久性 Durability

持久性表示事务一旦提交，修改结果就应该永久保存到数据库中。

即使数据库重启，只要事务已经 `COMMIT`，提交后的数据也不应该丢失。

## 4. MySQL 的四种隔离级别

MySQL 支持四种事务隔离级别：

- `READ UNCOMMITTED`
- `READ COMMITTED`
- `REPEATABLE READ`
- `SERIALIZABLE`

隔离级别从低到高，隔离性越来越强，并发性能通常越来越低。

### 4.1 READ UNCOMMITTED

读未提交。

一个事务可以读到另一个事务尚未提交的数据。

问题：

- 可能发生脏读。

这种隔离级别很少在业务系统中使用。

### 4.2 READ COMMITTED

读已提交。

一个事务只能读到其他事务已经提交的数据。

特点：

- 可以避免脏读。
- 可能出现不可重复读。

很多数据库默认使用这个隔离级别，例如 Oracle。

### 4.3 REPEATABLE READ

可重复读。

同一个事务中，多次读取同一批数据，结果保持一致。

特点：

- 可以避免脏读。
- 可以避免不可重复读。
- 在 MySQL InnoDB 中，配合 MVCC 和锁机制可以较好处理幻读问题。

MySQL InnoDB 默认隔离级别是 `REPEATABLE READ`。

### 4.4 SERIALIZABLE

串行化。

隔离级别最高，事务基本按顺序执行。

特点：

- 可以避免脏读、不可重复读、幻读。
- 并发性能最低。
- 一般只在对一致性要求极高、并发量不大的场景使用。

## 5. 并发事务常见问题

### 5.1 什么是脏读

脏读是指一个事务读到了另一个事务还没有提交的数据。

示例：

```text
事务 A 修改 score=99，但还没有 COMMIT。
事务 B 查询到了 score=99。
事务 A 后来 ROLLBACK。
事务 B 刚才读到的数据就是脏数据。
```

脏读的问题是：读到的数据可能最终根本不会生效。

### 5.2 什么是不可重复读

不可重复读是指同一个事务中，两次读取同一行数据，结果不一样。

示例：

```text
事务 A 第一次查询学生 903，score=80。
事务 B 修改学生 903 的 score=99 并 COMMIT。
事务 A 第二次查询学生 903，score=99。
```

事务 A 在同一个事务里两次读取同一行，结果不同，这就是不可重复读。

### 5.3 什么是幻读

幻读是指同一个事务中，两次按相同条件查询，第二次出现了第一次没有的记录，或者记录数量发生变化。

示例：

```text
事务 A 查询 score >= 90 的学生，有 3 条。
事务 B 新增一个 score=95 的学生并 COMMIT。
事务 A 再次查询 score >= 90 的学生，变成 4 条。
```

事务 A 感觉好像出现了一条“幻影”数据，这就是幻读。

### 5.4 幻读和不可重复读的区别

不可重复读关注的是同一行数据的内容变化。

例如：

```text
第一次查询 id=903，score=88。
另一个事务把 id=903 的 score 改成 99 并提交。
第二次查询 id=903，score=99。
```

这说明同一行的字段值变了。

幻读关注的是同一条件下结果集的数量变化。

例如：

```text
第一次查询 score >= 80，有 5 条数据。
另一个事务插入一条 score=90 的学生并提交。
第二次查询 score >= 80，变成 6 条数据。
```

这说明符合条件的记录变多了，好像出现了“幻影”记录。

简单区分：

- 不可重复读：同一行数据内容变了。
- 幻读：同一范围查询结果集变了，通常是新增或删除导致行数变化。

## 6. MySQL 默认隔离级别是什么

MySQL InnoDB 默认事务隔离级别是：

```sql
REPEATABLE READ
```

可以使用下面的 SQL 查看当前会话隔离级别：

```sql
SELECT @@transaction_isolation;
```

也可以查看全局隔离级别：

```sql
SELECT @@global.transaction_isolation;
```

## 7. MVCC、快照读和当前读

### 7.1 什么是 MVCC

MVCC 是 Multi-Version Concurrency Control，多版本并发控制。

可以简单理解为：数据库给同一行数据保存多个版本，让读操作尽量不阻塞写操作，写操作也尽量不阻塞普通读操作。

InnoDB 中的 MVCC 主要依赖：

- 隐藏字段：记录创建版本、删除版本等内部信息。
- undo log：保存旧版本数据。
- Read View：决定当前事务能看到哪些版本的数据。

在 `REPEATABLE READ` 隔离级别下，同一个事务第一次快照读时会生成 Read View，后续普通查询继续基于这个视图读取，所以同一事务内多次查询结果更稳定。

### 7.2 MVCC 解决了什么问题

MVCC 主要解决读写并发问题。

如果没有 MVCC，读操作和写操作更容易互相阻塞：

- 一个事务正在写数据，另一个事务读数据可能要等待。
- 一个事务正在读数据，另一个事务写数据可能也要等待。

有了 MVCC 后，普通 `SELECT` 可以读取历史版本快照，不必总是等待正在修改数据的事务提交。这能提升并发性能，同时减少脏读、不可重复读等问题。

### 7.3 什么是快照读

快照读是指读取某个时间点的数据快照，而不是一定读取最新数据。

普通 `SELECT` 通常是快照读：

```sql
SELECT * FROM student WHERE id = '903';
```

在 MySQL InnoDB 的 `REPEATABLE READ` 隔离级别下，同一个事务内多次普通 `SELECT` 通常读取同一份一致性快照。

本项目中的普通查询一般是快照读，例如：

- 查询全部学生。
- 查询当前用户创建的学生。
- 根据 id 查询学生详情。
- 分页条件查询学生。

### 7.4 什么是当前读

当前读是指读取数据库中最新已提交的数据，并且通常会加锁，保证后续修改或判断基于最新数据。

`SELECT ... FOR UPDATE` 属于当前读：

```sql
SELECT * FROM student WHERE id = '903' FOR UPDATE;
```

`UPDATE`、`DELETE`、`INSERT` 也属于当前读相关操作，因为它们要基于最新数据进行写入或加锁。

本项目中的修改、删除、批量删除都属于当前读相关写操作：

- 修改学生：`UPDATE student ...`
- 删除学生：`DELETE FROM student WHERE id = ?`
- 批量删除学生：`DELETE FROM student WHERE id IN (...)`

## 8. InnoDB 锁和幻读控制

### 8.1 什么是行锁

行锁是锁住某一行记录。

例如：

```sql
SELECT * FROM student WHERE id = '903' FOR UPDATE;
```

如果 `id='903'` 存在，InnoDB 会对这行记录加锁。其他事务如果想修改这行数据，通常需要等待当前事务提交或回滚。

行锁粒度小，并发性能比表锁更好。

### 8.2 什么是间隙锁

间隙锁是锁住索引记录之间的范围，也就是锁住“空隙”。

例如当前 `score` 索引中有 80 和 90 两个值，80 到 90 之间就是一个间隙。InnoDB 可以通过间隙锁阻止其他事务往这个范围插入新记录。

间隙锁主要用于防止范围查询中的幻读。

### 8.3 什么是临键锁 Next-Key Lock

临键锁，也叫 Next-Key Lock，可以理解为：

```text
临键锁 = 行锁 + 间隙锁
```

它既锁住已有记录，也锁住记录前后的间隙。

例如：

```sql
SELECT * FROM student WHERE score >= 80 FOR UPDATE;
```

在 `REPEATABLE READ` 下，如果这个范围查询走了索引，InnoDB 可能会使用临键锁锁住符合条件的记录以及相关间隙，减少其他事务插入新的符合条件记录造成幻读。

### 8.4 MySQL InnoDB 在 REPEATABLE READ 下如何减少幻读问题

InnoDB 在 `REPEATABLE READ` 下主要通过两类机制减少幻读：

- 普通 `SELECT`：使用 MVCC 一致性快照。同一个事务内多次普通查询通常看到同一份快照，所以不会看到其他事务新提交的“幻影”数据。
- 当前读：使用行锁、间隙锁、临键锁。例如 `SELECT ... FOR UPDATE`、`UPDATE`、`DELETE` 会读取最新数据并加锁，阻止其他事务插入或修改会影响当前范围判断的数据。

需要注意：是否使用间隙锁、临键锁，和隔离级别、索引、SQL 条件、优化器执行计划有关。范围查询如果没有合适索引，锁的范围可能更大。

## 9. MySQL Workbench 事务实验结果

### 9.1 READ COMMITTED 下可能出现不可重复读

实验过程：

```text
窗口 A 开启事务，第一次查询 id=903，看到 score=88。
窗口 B 修改 id=903 的 score=99，并执行 COMMIT。
窗口 A 在同一个事务内第二次查询 id=903，看到 score=99。
```

说明：

- 在 `READ COMMITTED` 隔离级别下，一个事务每次普通 `SELECT` 都可以看到其他事务已经提交的新数据。
- 窗口 A 在同一个事务内两次读取同一行数据，第一次是 `score=88`，第二次是 `score=99`。
- 同一个事务内两次读取同一行结果不同，这就是不可重复读。

结论：`READ COMMITTED` 可以避免脏读，但可能出现不可重复读。

### 9.2 REPEATABLE READ 下普通 SELECT 可以避免不可重复读

实验过程：

```text
窗口 A 开启事务，第一次查询 id=903，看到 score=88。
窗口 B 修改 id=903 的 score=100，并执行 COMMIT。
窗口 A 在同一个事务内第二次普通 SELECT 查询 id=903，仍然看到 score=88。
```

说明：

- 在 `REPEATABLE READ` 隔离级别下，同一个事务内的普通 `SELECT` 会基于一致性快照读取数据。
- 窗口 B 虽然已经提交了 `score=100`，但窗口 A 的事务还没有结束，所以窗口 A 第二次普通 `SELECT` 仍然看到第一次查询时的 `score=88`。
- 这体现了 InnoDB 的 MVCC 机制：同一个事务内普通查询看到的是同一份快照。

结论：`REPEATABLE READ` 下普通 `SELECT` 使用一致性快照，可以避免不可重复读。

### 9.3 REPEATABLE READ 下普通 SELECT 范围查询是快照读

实验过程：

```text
窗口 A 在 REPEATABLE READ 下开启事务。
窗口 A 第一次执行 SELECT * FROM student WHERE score >= 80，查到 6 行。
窗口 B 插入一条 score=90 的新学生，并执行 COMMIT。
窗口 A 在同一个事务内第二次执行同样的普通 SELECT，仍然查到 6 行。
```

说明：

- 普通 `SELECT` 是快照读，不加锁，读取的是一致性快照。
- 在 `REPEATABLE READ` 下，窗口 A 第一次普通查询时形成一致性快照。
- 窗口 B 后续插入的新学生虽然已经提交，但窗口 A 的事务还没结束，所以第二次普通 `SELECT` 仍然基于同一份快照读取，结果还是 6 行。

结论：`REPEATABLE READ` 下普通 `SELECT` 是快照读，同一个事务内看到一致性快照。

### 9.4 SELECT ... FOR UPDATE 当前读会加锁

实验过程：

```text
窗口 A 执行 SELECT * FROM student WHERE score >= 80 FOR UPDATE，并保持事务不提交。
窗口 B 执行 UPDATE student SET score = 95 WHERE id = '903'。
窗口 B 被阻塞等待。
窗口 A 执行 COMMIT 后，窗口 B 的 UPDATE 才继续执行成功。
```

说明：

- `SELECT ... FOR UPDATE` 是当前读，会读取最新已提交数据，并对读取到的数据加锁。
- 窗口 A 持有锁且事务未提交时，窗口 B 修改相关数据会被阻塞等待。
- 窗口 A 提交事务释放锁后，窗口 B 的 `UPDATE` 才能继续执行。

结论：`SELECT ... FOR UPDATE` 是当前读，会加锁，可能阻塞其他事务的修改。

### 9.5 快照读和当前读对比

| 对比项 | 快照读 | 当前读 |
| --- | --- | --- |
| 典型 SQL | 普通 `SELECT` | `SELECT ... FOR UPDATE`、`UPDATE`、`DELETE`、`INSERT` |
| 读取内容 | 一致性快照 | 最新已提交数据 |
| 是否加锁 | 通常不加锁 | 通常会加锁 |
| 主要作用 | 提高普通查询并发能力 | 保证写操作或加锁查询基于最新数据 |

简单记忆：

- 普通 `SELECT` 是快照读，不加锁，读取一致性快照。
- `SELECT ... FOR UPDATE` 是当前读，读取最新数据并加锁。
- `UPDATE`、`DELETE`、`INSERT` 也属于当前读相关操作。

### 9.6 实验总结

- `READ COMMITTED`：每次 `SELECT` 都能看到其他事务已提交的新数据。
- `REPEATABLE READ`：同一个事务内普通 `SELECT` 看到同一份快照。
- MVCC 主要服务于普通 `SELECT` 这种快照读。
- `FOR UPDATE` 会走当前读并加锁，可能阻塞其他事务修改相关数据。
- MySQL InnoDB 默认隔离级别是 `REPEATABLE READ`。

## 10. 本项目中哪些操作适合加事务

本项目中，学生相关写操作适合使用事务：

- 添加学生：`addStudent`
- 修改学生：`updateStudent`
- 删除学生：`deleteStudent`
- 批量删除学生：`deleteBatch`

这些操作会修改数据库数据，执行过程中如果出现异常，应该回滚，避免数据处于不完整状态。

批量删除尤其适合使用事务。如果中间出错，需要事务保证要么全部成功，要么全部失败。

查询操作通常不会修改数据，可以使用只读事务：

```java
@Transactional(readOnly = true)
```

只读事务可以表达方法语义，也可能帮助数据库或框架做一些只读优化。

普通查询一般是快照读，修改、删除、批量删除是当前读相关写操作。批量删除适合事务，因为要么全部删除成功，要么失败回滚，避免删除一部分后就中断。

## 11. @Transactional 在项目中的作用

`@Transactional` 是 Spring 提供的声明式事务注解。

它的作用是：让方法内数据库操作在同一个事务中执行。方法开始时开启事务，方法正常结束时提交事务，方法抛出运行时异常时回滚事务。

写操作可以使用：

```java
@Transactional
```

查询操作可以使用：

```java
@Transactional(readOnly = true)
```

在本项目中：

- 添加学生、修改学生、删除学生、批量删除学生属于写操作，适合使用 `@Transactional`。
- 查询全部学生、查询当前用户创建的学生、查询学生详情、分页查询属于查询操作，可以使用 `@Transactional(readOnly = true)`。
- 批量删除如果中间出错，需要事务保证要么全部成功，要么全部失败。
- 普通查询一般是快照读；修改、删除、批量删除属于当前读相关写操作。

需要注意：`@Transactional` 通常应该加在 `service` 层方法上，因为事务属于业务操作边界，而不是 controller 或 mapper 的职责。

## 12. 常见面试题和回答

### 1. 什么是事务？

事务是一组数据库操作的执行单元，这组操作要么全部成功，要么全部失败。事务用于保证数据操作的完整性和一致性。

### 2. 事务的 ACID 是什么？

ACID 指原子性、一致性、隔离性、持久性。原子性保证全部成功或全部失败；一致性保证事务前后数据合法；隔离性保证并发事务之间互不随意干扰；持久性保证提交后的数据永久保存。

### 3. 什么是原子性？

原子性表示一个事务中的多个操作不可再拆分，要么全部提交，要么全部回滚。例如批量删除学生时，如果中间失败，就应该整体回滚。

### 4. 什么是一致性？

一致性表示事务执行前后，数据库都处于正确状态。它通常由数据库约束、业务校验和事务共同保证。

### 5. 什么是隔离性？

隔离性表示多个事务并发执行时，彼此之间要有隔离，避免读到未提交数据或不稳定数据。隔离性由事务隔离级别控制。

### 6. 什么是持久性？

持久性表示事务一旦提交，修改结果就会持久保存到数据库中，即使数据库重启也不应该丢失。

### 7. MySQL 有哪些隔离级别？

MySQL 有四种隔离级别：`READ UNCOMMITTED`、`READ COMMITTED`、`REPEATABLE READ`、`SERIALIZABLE`。隔离级别越高，并发问题越少，但性能成本通常越高。

### 8. MySQL 默认隔离级别是什么？

MySQL InnoDB 默认隔离级别是 `REPEATABLE READ`，也就是可重复读。

### 9. 什么是脏读？

脏读是指一个事务读到了另一个事务还没有提交的数据。如果另一个事务后来回滚，那么读到的数据就是无效数据。

### 10. 什么是不可重复读？

不可重复读是指同一个事务中，两次读取同一行数据，结果不一致。通常是因为另一个事务在两次读取之间修改并提交了这行数据。

### 11. 什么是幻读？

幻读是指同一个事务中，两次按相同条件查询，结果集数量发生变化，例如第二次查询多出了第一次没有的数据。

### 12. 幻读和不可重复读有什么区别？

不可重复读关注同一行数据内容变化，例如同一个事务里两次查询 `id=903`，成绩从 88 变成 99。幻读关注范围查询结果集变化，例如两次查询 `score >= 80`，第二次多出一条新插入的学生数据。

### 13. MVCC 是什么？

MVCC 是多版本并发控制。它通过保存数据的多个版本，让普通读操作可以基于快照读取旧版本数据，从而减少读写阻塞，提高并发性能。

### 14. MVCC 解决了什么问题？

MVCC 主要解决读写并发问题。普通查询可以读取一致性快照，不必总是等待写事务提交，从而减少读写阻塞，并帮助解决脏读、不可重复读等问题。

### 15. 什么是快照读？

快照读是读取某个时间点的数据快照。普通 `SELECT` 一般是快照读，在 `REPEATABLE READ` 下，同一个事务内多次普通查询通常看到同一份快照。

### 16. 什么是当前读？

当前读是读取最新已提交数据，并且通常会加锁。`SELECT ... FOR UPDATE`、`UPDATE`、`DELETE`、`INSERT` 都属于当前读相关操作。

### 17. 什么是行锁、间隙锁、临键锁？

行锁锁住已有记录；间隙锁锁住索引记录之间的范围，防止插入新记录；临键锁是行锁加间隙锁，既锁记录也锁间隙，常用于范围当前读，帮助减少幻读。

### 18. MySQL InnoDB 在 REPEATABLE READ 下如何减少幻读？

普通 `SELECT` 通过 MVCC 一致性快照避免在同一事务内看到新插入的数据；`SELECT ... FOR UPDATE`、`UPDATE`、`DELETE` 这类当前读通过行锁、间隙锁、临键锁控制范围内的数据变化。

### 19. `@Transactional` 有什么作用？

`@Transactional` 用来声明事务边界。方法开始时开启事务，正常结束时提交，出现运行时异常时回滚。本项目的添加、修改、删除、批量删除学生等写操作适合使用它。

### 20. 本项目哪些地方适合用事务？

添加学生、修改学生、删除学生、批量删除学生都属于写操作，适合使用 `@Transactional`。查询操作可以使用 `@Transactional(readOnly = true)`。批量删除如果中间出错，需要事务保证要么全部成功，要么全部失败。

### 21. 面试总结：快照读、当前读和项目事务怎么串起来？

MVCC 主要服务于普通 `SELECT` 这种快照读，让查询读取一致性快照，减少读写阻塞。`SELECT ... FOR UPDATE` 会走当前读并加锁，读取最新已提交数据，可能阻塞其他事务修改相关记录。项目中修改、删除、批量删除属于写操作，需要事务保证一致性，尤其是批量删除，要么全部删除成功，要么失败回滚。
